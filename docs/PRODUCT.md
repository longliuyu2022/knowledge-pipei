# 同频：知乎灵魂对对碰

参赛赛道：知乎黑客松 2026 · 灵魂匹配局。核心体验：用共同的知识兴趣，让陌生人拥有自然、具体的交流起点。

## 问题与目标用户

在知乎，用户通过创作、收藏和关注积累了独特的兴趣轨迹；从阅读内容走到认识同好，往往缺少一个合适的开场。同频面向愿意认真交流的学生、跨学科学习者、创作者和项目伙伴，让用户看见“我们为什么值得聊一聊”。

用户可以从三个自选兴趣开始，不必先证明自己是某个领域的专家。应用只使用用户主动填写或明确授权提供的资料，知识画像描述兴趣倾向，不评价知识水平。

## 一次完整的相遇

1. 选择 3–8 个兴趣，补充喜欢的交流方式、期待以及正在思考的问题。
2. AI 整理知识兴趣，生成称号、兴趣解读和可回看的依据；用户查看六维雷达并可随时修改。
3. 选择是否加入真实匹配。公开内容包括昵称、画像、自述、问题和交流偏好，原始导入摘要不对伙伴开放。
4. 查看同频或互补伙伴。共同点、交流方式与新视角均有具体说明，四项评分可以复算。
5. 从轻松开场、深入一点、一起行动三种破冰问题中选择自己的开场，决定是否发出邀请。
6. 对方接受后开启真实双人对话。资料、邀请、已发送消息与收藏持久保存，可以撤回发现、屏蔽或删除。

体验模式提供八位虚构角色展示不同知识方向，明确标记来源并禁止向其发送邀请。真实模式完整保留冷启动空态，只有自愿参与者进入候选池。

还可以选择即时相遇：进入「灵魂匹配」手动开始，系统仅在同时在线、主动等待的用户中配对；可以选择同频或互补方式、限定共同兴趣。双方各自确认后建立聊天，支持取消或换一个。每轮最多等待 3 分钟，候选确认时间为 60 秒；离线超过 45 秒会退出。临时配对不用开启全局发现，只向本次另一方展示公开画像，既有连接继续保留。配对页展示真实等待与确认人数，提供公开邀请链接；邀请不会指定配对对象，双方仍各自决定是否开始。

## AI 的实际作用

**兴趣理解。** 文本模型把自选兴趣、自述和授权摘要组织为可读的兴趣描述。每次结果需要引用至少两条真实输入依据，输出不符合约定时使用明确标注的规则分析。

**匹配解释。** 数值匹配采用可复算的多维计算，AI 根据双方提供的资料解释共同话题与视角差异。模型不改写分数，不推断没有提供的人生经历或敏感特征。

**破冰生成。** 针对双方正在关注的问题，生成三种具体的开场。配置知乎内容能力后可附带搜索摘要与原文链接，引用必须来自实际返回的来源。用户亲自决定复制或发送，系统不代替伙伴回复。已建立聊天默认展示双方共同兴趣和三条规则开场，点选后追加到草稿并保留已写内容；用户主动点击「生成更多灵感」时才使用模型与知乎搜索。

当前部署的文本模型为用户指定兼容服务中的 `deepseek-v4-flash`，三项实际调用链均已验收。可选语义 embedding 适配已实现并经过协议测试，当前线上仍使用知识主题向量。

## 匹配方式

同频指数由知识领域接近程度（45%）、具体兴趣重合（20%）、交流方式接近程度（20%）、交流期待重合（15%）构成。知识领域采用目录中六维主题坐标的余弦相似度，具体兴趣使用带权重的重合度。自述与导入摘要中的明确关键词可补充兴趣线索，强度有上限。

互补模式在共同话题的基础上衡量可提供的新视角，采用视角互补（35%）、共同兴趣（25%）、交流方式（25%）、交流期待（15%）。它帮助用户探索熟悉圈子之外的方向，不承诺关系结果。

星图使用 D3 Force 排布用户、兴趣与候选伙伴。连线代表与自己的共同兴趣，支持筛选、拖动、缩放及详情导航。

## 知乎生态接入

官方 OAuth 身份接口、授权用户的创作摘要/关注/近期收藏接口，以及站内搜索均已实现。导入前让用户选择来源，每类最多读取十条，保留来源链接并区分摘要与全文；不请求不存在的点赞或浏览历史能力。数据连接检查按每项一条验证五类公开数据，空数据、错误和未检查分别展示，只保存检查元数据，不自动加入画像。

知乎赛事凭证已通过 systemd Credentials 配置，官方 Skill 初始化、CLI 凭证验证和最小本人内容读取已通过，线上入口可打开知乎授权页。官方登录和导入另有 Mock 协议测试，仍需使用者本人完成最终授权及 OAuth 数据验收。产品的手动兴趣、真实模型、实时配对和双向同意后的聊天可独立使用，OAuth 回调严格校验 state。

同频通过好问题引导用户回到知乎原文阅读，通过共同兴趣建立持续讨论关系，给社区内容增加“围绕它认识一个人”的使用场景。

## 实现与交付

- React/TypeScript/Vite 前端，响应式桌面与手机页面；图片卡片在浏览器本地绘制并导出。
- Express + SQLite 后端，随机 HttpOnly 会话、来源与 CSRF 校验、版本冲突处理。
- SSE 更新邀请和聊天，消息支持幂等重试与历史分页。
- 模型输出校验、缓存去重、请求限速、显式降级与错误反馈。
- Caddy HTTPS + systemd 单机部署，源码与自动化验证可复现。

单机内存中的在线队列、限流、OAuth Token 和实时事件通道适合本次参赛部署。服务重启会结束尚未完成的排队；已建立连接与聊天保存在 SQLite。扩展为多实例服务时，需要共享队列、Token、限流和消息通道。后续应通过真实试用验证邀请接受率、对话质量与用户留存，当前没有虚构这些指标。
